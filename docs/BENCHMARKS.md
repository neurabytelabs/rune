## Methodology

Blind pairwise A/B: each prompt in the committed, versioned prompt set runs
through two arms — **control** (the raw prompt) and **treatment** (the prompt
amplified by RUNE's 8-layer enhancement) — on the same model with identical
parameters. Responses are anonymized (per-judge randomized A/B order) and
scored by independent judges on a 5-criterion rubric with a forced winner.
Majority vote decides each pair; split decisions get an adversarial verifier.
See `benchmark/JUDGE_PROTOCOL.md` for the full contract.

## Result

In blind pairwise comparison, RUNE-amplified prompts were preferred in **19.6%** of decided pairs (95% CI [10.2%, 29.3%]; 46 decided of 50 pairs; ties: 8.0%; exact binomial sign test p = 4.056e-05).

## Is this a harness artifact?

Before publishing, we hand-read the 5 coding-domain pairs (0 treatment wins) end to
end — prompt, full enhanced XML, both outputs, and all judge rationales unblinded.
Enhanced prompts are well-formed and substantive (not truncated); control and
treatment outputs are comparable in length (ruling out a length-penalty artifact);
and judge rationales cite specific technical defects, not generic "structure"
complaints — e.g. a treatment response's Git commands produced a detached HEAD
(breaking the workflow it described), even though the enhancement's own
self-generated QA layer explicitly asked "Are the Git commands syntactically
correct?" This is a small sample and not a proven causal mechanism, but it is
enough to rule out a harness bug or rubric artifact as the explanation. See the
full run report for the detailed spot-check.

## Limitations

- **The protocol is label-blind, not style-blind.** RUNE-amplified responses may self-reveal through
  structural artifacts. Judges are instructed not to reward structure per se; judge
  agreement and tie rates above are the honesty diagnostics.
- **Single sample per cell** at the configured temperature — the benchmark measures the
  output distribution users actually get, not a best-of-N.
- **Generation model family is Gemini only**; judging is cross-family but single-family
  (see JUDGE_PROTOCOL.md for the judge configuration of this run).
- The prompt set was partly authored by RUNE's developer; prompt IDs, sources, and the
  full set are committed for scrutiny.
- **Judging used two panels**: 21/50 pairs by a Claude/Fable panel, the remaining
  29/50 by a Claude Sonnet 5 panel (a mid-run usage-limit switch). Both panels
  independently found control winning by a wide margin — see the run report for the
  per-panel breakdown.

## Run it yourself

```bash
export RUNE_API_KEY=<your key>
wand bench generate --promptset benchmark/promptset_v1.jsonl
wand bench export
wand bench judge --api-url <any-openai-compat-endpoint> --model <judge-model>
wand bench ingest && wand bench report
```

The judge is pluggable: any judging system that honors
`benchmark/JUDGE_PROTOCOL.md` (an LLM endpoint, a multi-agent workflow, or a
human panel) produces verdicts this harness can analyze.
